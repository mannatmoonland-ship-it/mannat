Help & Instructions

How to Create a Backup

  1. Click Create Snapshot.
  2. The application collects Firestore data from the active Firebase project.
  3. The data is packaged into a ZIP file and saved in the local backups/ folder.
  4. The backup appears in Snapshot History.
  5. Verification status indicates whether the ZIP and its contents passed integrity checks.
  6. Use Open Folder in the history row or Open Backup Folder to locate it on this computer.

A Firestore backup does not include Firebase Authentication accounts, Storage files, security rules, or Cloud Functions.

How to Restore a Backup

  1. Select a verified ZIP from Snapshot History or Restore Snapshot.
  2. Choose Existing Firebase project or New Firebase project.
  3. Enter the destination Firebase Project ID.
  4. Select the destination project's service-account JSON file.
  5. Provide that destination's public Firebase Web App config, then click Validate Destination & Preview.
  6. Review the source and destination IDs, collections, document counts, existing data, and conflicts.
  7. For conflicts, choose Skip existing documents, Replace existing documents, or Cancel Restore.
  8. Type the destination Project ID to confirm only after carefully reviewing the destination.
  9. Wait for the batched restore and document verification to finish.
  10. Review the final status and any failed, overwritten, or skipped documents.
WARNING

Restoring into an existing Firebase project can modify its data. Always verify the destination project before confirming a restore. Create a backup of the destination before overwriting existing data.

Before You Restore

  • Verify the ZIP backup.
  • Confirm the destination Project ID.
  • Keep service-account credentials private.
  • Avoid restoring into the production project during testing.
  • Do not switch the production application until the restored project has been checked.

How to Switch the Application to the Restored Project

  1. Restore the backup to the intended Firebase project.
  2. Verify that the restored collections and documents are present.
  3. Return to this Snapshot page.
  4. Use Switch Application to Restored Project.
  5. Review the current and destination Firebase Project IDs.
  6. Confirm the switch only when the destination is correct.
  7. The application updates its Firebase configuration to use the restored project.
  8. The browser reloads to use the updated configuration; restart the server only if your deployment requires it.
  9. Sign in if prompted and verify that expected modules and data are available.
IMPORTANT

Switching the application changes which Firebase project the app uses. It does not merge the two projects. The original Firebase project remains separate.
